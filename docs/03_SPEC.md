# 03_SPEC — المواصفات التفصيلية

## 1. بنية التطبيق
```
src/
  app/
    (public)/            # الرئيسية، المنهاج، الدروس، أرشيف الامتحانات
    (auth)/              # دخول، تسجيل، استعادة
    (student)/           # لوحة الطالب
    (parent)/            # بوابة الولي
    (center)/            # جناح المركز (مدير/سكرتير/أستاذ)
    (admin)/             # المشرف العام: المنهاج والمراكز
    api/                 # فقط للـ webhooks والتصدير
  lib/
    db.ts                # عميل Prisma الوحيد
    tenant.ts            # تقييد الاستعلامات بالمركز/الفرع
    auth.ts, permissions.ts
    money.ts             # دوال المال (أعداد صحيحة)
    schedule.ts          # توليد الحصص وكشف التعارض
    billing.ts           # توليد الفواتير والدفعات
    i18n/, validators/ (Zod), audit.ts, notify/ (محوّلات)
  components/ui/ , features/<module>/
prisma/ schema.prisma, migrations/, seed/
tests/ unit/, integration/, e2e/
```
- Server Components افتراضياً، Server Actions للتعديل، كل Action: `authenticate → authorize → validate(Zod) → tenantScope → execute → audit`.

## 2. الأدوار والصلاحيات
| الدور | النطاق | يستطيع |

| SUPER_ADMIN | المنصة | إدارة المنهاج، المراكز، الاشتراكات، الدعم |
| CENTER_OWNER | مركز | كل شيء داخل المركز بما فيه المالية والتقارير والموظفين |
| BRANCH_MANAGER | فرع | الطلاب، الأفواج، الجداول، الحضور، المدفوعات، تقارير الفرع |
| SECRETARY | فرع | تسجيل الطلاب، الحضور، قبض الدفعات، دون إعدادات أو أجور |

- تنفَّذ في `permissions.ts` كجدول (role × action × resource) مع اختبارات مصفوفية، وليس شروطاً متناثرة.

## 3. وحدة المنهاج والمحتوى
- **الهيكل:** `Cycle(PRIMARY|MIDDLE|SECONDARY)` ← `Level` ← `Stream` (للثانوي) ← `Subject` ← `Unit` ← `Lesson`.
- `LevelSubject` يحمل المعامل والحجم الساعي كقيم قابلة للتعديل ولكل شعبة.
- **الدرس:** عنوان، ملخص، محتوى Markdown/MDX، `videoUrl` (روابط خارجية فقط)، مرفقات، فصل دراسي (1/2/3)، صعوبة، وسوم، حالة النشر، رؤية، مؤلف.
- **أرشيف الامتحانات:** نوع (PRIMARY_CERT, BEM, BAC, TRIMESTER_EXAM), سنة، دورة (عادية/استدراكية)، مادة، شعبة، ملف الموضوع، ملف الحل، مدة، ملاحظات.
- **البحث:** عمود `searchText` مُطبَّع (إزالة التشكيل، توحيد أ/إ/آ→ا، ى→ي، ة→ه للبحث) + فهرس Postgres (`pg_trgm` أو tsvector).
- **الرؤية:** `PUBLIC` للجميع، `CENTER` لطلاب المركز، `GROUP` لأفواج محددة. تُفحص في طبقة الاستعلام.

## 4. الاختبارات والواجبات
- `Quiz` ← `Question(type, prompt, explanation, points)` ← `Option(text, isCorrect)`؛ الإجابة القصيرة تقارن بقائمة إجابات مقبولة بعد التطبيع.
- `Attempt(score, maxScore, answers JSON, startedAt, finishedAt)`؛ الحد الأقصى للمحاولات قابل للضبط؛ الدرجة تُعرض /20 بالتناسب.
- `Assignment` تُسند لفوج أو مستوى؛ `Submission` بنص/ملف؛ تصحيح الأستاذ: علامة (0–20، خطوة 0.25) وملاحظات.
- يمنع الطالب رؤية الحل قبل انتهاء المحاولات/الموعد حسب إعداد الأستاذ.

## 5. وحدة المركز

### 5.1 الأفواج والتسجيل
- `Group(branchId, subjectId, levelId, streamId?, teacherId, roomId?, capacity, feePlanId, startDate, endDate?, status)`.
- `Enrollment(studentId, groupId, startDate, endDate?, status ACTIVE|WAITLIST|LEFT, discountId?)`؛ يمنع تكرار تسجيل نشط لنفس الطالب/الفوج؛ عند الامتلاء ينتقل الطالب للانتظار؛ عند شغور مقعد يُقترح أول المنتظرين.

### 5.2 الجدول وكشف التعارض
- `ScheduleSlot(groupId, weekday, startTime, endTime, roomId)` دوري.
- `Session(groupId, date, startTime, endTime, roomId, teacherId, status PLANNED|DONE|CANCELLED|MAKEUP)` تُولَّد من الشرائح لنطاق تواريخ، بعملية idempotent (مفتاح فريد: groupId+date+startTime).
- **التعارض يُرفض عند الحفظ** إذا تقاطعت الفترات لنفس: القاعة، الأستاذ، أو طالب مسجّل في فوجين متزامنين (تحذير لا رفض للطالب). التقاطع: `startA < endB && startB < endA`.
- حالات حدّية يجب اختبارها: حصة تنتهي لحظة بدء أخرى (لا تعارض)، حصص تعبر منتصف الليل (ممنوعة)، تغيير القاعة لحصة واحدة.

### 5.3 الحضور
- `Attendance(sessionId, studentId, status PRESENT|ABSENT|LATE|EXCUSED, note, markedBy, markedAt)` بفهرس فريد (sessionId, studentId).
- لا يُسجَّل الحضور لحصة مستقبلية؛ تعديل الحضور بعد 48 ساعة يتطلب دور مدير ويُسجَّل في التدقيق.
- واجهة سريعة للهاتف: قائمة الفوج، لمسة واحدة لتبديل الحالة، «الكل حاضر» ثم استثناء الغائبين.

### 5.4 الفوترة
- `FeePlan(type MONTHLY|PER_SESSION|TERM|PACKAGE, amount, registrationFee?)`.
- توليد الفواتير: لكل تسجيل نشط في الشهر M فاتورة واحدة فريدة (enrollmentId, period)؛ المبلغ = الرسوم − الخصم؛ للحصة: عدد الحصص الحاضرة × السعر؛ تناسب جزئي للشهر الأول بقاعدة قابلة للضبط (كامل/نصفي/بالحصص).
- `Invoice(status DRAFT|ISSUED|PARTIAL|PAID|VOID, total, paid)`، `Payment(amount, method CASH|CCP|BARIDIMOB|BANK|OTHER, receiptNo, paidAt, receivedBy)`.
- الدفعة لا تتجاوز المتبقي إلا بتأكيد صريح يتحول الفائض إلى رصيد للطالب.
- ترقيم الإيصالات متسلسل لكل فرع وسنة دون فجوات (داخل معاملة قاعدة بيانات).
- لا حذف لدفعة؛ الإلغاء بقيد عكسي + سبب + تدقيق.
- الصندوق اليومي: مجموع الدفعات النقدية لكل مستلم؛ الإقفال يمنع التعديل بعده.

### 5.5 أجور الأساتذة
- `TeacherContract(model PERCENT|HOURLY|PER_SESSION|FIXED, rate, groupId?)`.
- `Payout(period, gross, advances, net, status)`؛ PERCENT = نسبة من المحصَّل (لا المفوتر) في الفترة، وتُعرض طريقة الحساب في الكشف.

### 5.6 المصاريف والتقارير
- `Expense(category, amount, date, branchId, note)`.
- التقارير تُحسب بالاستعلام مع فهارس، مع تخزين مؤقت قصير؛ كل رقم في لوحة التحكم يقبل «عرض التفاصيل» يفتح القائمة المكوّنة له.

## 6. الإشعارات
- واجهة `NotificationChannel { send(to, template, data) }` بمحوّلات: Internal (افتراضي)، WhatsAppLink، SMS (فارغ حتى توفر مزوّد). القوالب بالعربية مع متغيرات (`{studentName}`, `{date}`, `{group}`).

## 7. الشاشات الأساسية (MVP)
1. الرئيسية العامة وتصفح المنهاج وصفحة الدرس وأرشيف الامتحانات.
2. لوحة الطالب: تقدمي، جدولي، واجباتي، نتائجي.
3. بوابة الولي: أبنائي، الغياب، الدفع، العلامات.
4. لوحة المركز: ملخص اليوم (حصص، حاضرون، دفعات، متأخرات).
5. الطلاب (قائمة+ملف)، الأفواج، الأساتذة، القاعات.
6. الجدول الأسبوعي (عرض شبكي) وتسجيل الحضور.
7. الفواتير والدفعات والإيصال والصندوق، أجور الأساتذة، المصاريف.
8. التقارير، الإعدادات (فرع، سنة دراسية، قوالب، صلاحيات).
9. لوحة المشرف: المنهاج، المحتوى، المراكز.

## 8. قواعد التوطين
- التواريخ: ميلادية بصيغة `DD/MM/YYYY` مع أسماء أشهر عربية (جانفي/فيفري … أو يناير/فبراير حسب إعداد المستخدم).
- الأعداد: `1 500 دج`، مع الفاصل المناسب، وبدون كسور.
- الهاتف: التحقق بالتعبير النمطي `^(\+213|0)(5|6|7)\d{8}$` بعد إزالة الفراغات.
- العلامات: /20 بفاصلة عشرية (`14,25`)، المعدل بمعاملات المادة.
- الاتجاه: `dir="rtl"` على الجذر، وأيقونات الاتجاه تُعكس، والجداول تُقرأ من اليمين.
- الطباعة: CSS مخصص `@media print`، خط عربي مضمّن، لا اعتماد على مكتبات PDF لا تدعم ربط الحروف.

## 9. معايير القبول لكل وحدة (مختصر)
- **الجدول:** 15 حالة اختبار على الأقل لكشف التعارض.
- **الفوترة:** اختبارات خصائص (property tests) تثبت: مجموع الدفعات ≤ الإجمالي ما لم يؤكَّد فائض، وإعادة توليد الشهر لا تُنشئ فواتير مكررة.
- **الحضور:** لا تكرار، لا مستقبل، لا تعديل متأخر دون صلاحية.
- **العزل:** اختبار آلي يمر على كل Action ويحاول الوصول لمورد مركز آخر فيفشل.
